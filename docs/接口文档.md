# 1 统一响应接口形式和URL规范

## 1.1 统一响应接口

```json
{
  "code": 200,           // 业务状态码 (2开头成功, 4开头前端的问题, 5开头后端的问题)
  "message": "success",   // 给前端展示的提示文字
  "data": { ... }        // 具体的数据，没有数据就是 null
}
```

## 1.2 URL规范

/api/v1/具体信息

api表示这是请求地址，v1表示版本，方便迭代

# 2 功能接口

## 2.1 账户登录相关接口

### 2.1.1 账户注册

功能说明：前端发送用户名和密码

请求路径：/api/v1/auth/register

method：POST

请求头：Content-Type: application/json

请求体：

~~~json
{
  "userName": "昵称", 
  "password": "密码"  // 前端需预校验长度和字母数字组合
}
~~~

**请求参数说明：**


| 字段名   | 数据类型 | 是否必填 | 说明/约束规范                                   |
| :------- | :------- | :------- | :---------------------------------------------- |
| userName | String   | 是       | 长度 2-20，**去除首尾空格后校验**，不允许全空格 |
| password | String   | 是       | 长度 8-16，必须同时包含数字和字母               |

要求：

* 前后端都需要验证昵称和密码是否满足（可以用正则表达式来验证）
* 昵称要求是2到20位字符
* 密码要求仅允许包含大小写英文字母、数字及指定的特殊符号，严禁包含空格及中文字符，英文特殊符号如（_@!#$%^&*()-=+[]\\{}|:";',./<>?`\~）等等
* 后端检验没问题后要返回账号（10位随机）
* 后端要加密密码

成功响应格式

~~~json
{
      "code": 200,
      "message": "success",
      "data": {
        "accountNo": "8374921045",  // 把生成的账号返回，告诉用户用这个登录
        "userName": "昵称"
      }
}
~~~

失败响应格式

~~~json
{
      "code": 根据错误类型返回,
      "message": "具体错误分类",
      "data": null
}
~~~

接口返回约束


| **业务场景**   | **Code** | **Message (供前端直接作为 Toast 提示语)**      | **底层逻辑说明**                 |
| -------------- | -------- | ---------------------------------------------- | -------------------------------- |
| **正常成功**   | `200`    | `"注册成功！请牢记您的专属登录账号"`           | 数据落库成功，随机账号生成完毕   |
| **昵称长度错** | `400`    | `"注册失败：昵称长度必须为2到20个字符"`        | 后端校验`userName`长度失败       |
| **密码格式错** | `400`    | `"注册失败：密码必须为8-16位且包含数字和字母"` | 后端正则校验`password`失败       |
| **参数缺失**   | `400`    | `"注册失败：请求参数不完整，请检查填写"`       | `userName`或`password`为空       |
| **系统异常**   | `500`    | `"服务器繁忙，账号生成失败，请重试"`           | 数据库连接失败或账号生成碰撞超时 |

### 2.1.2 账户登录

功能说明：前端发送10位登录账号和密码，后端验证通过后返回身份令牌（Token）及基本信息

请求路径：/api/v1/auth/login

method：POST

请求头：Content-Type: application/json

请求体：

~~~json
{
  "accountNo": "8374921045",
    "password": "密码"
}
~~~

**请求参数说明：**


| **字段名** | **数据类型** | **是否必填** | **说明/约束规范**                    |
| ---------- | ------------ | ------------ | ------------------------------------ |
| accountNo  | String       | 是           | 必须为 10 位纯数字                   |
| password   | String       | 是           | 密码原码，去除首尾空格后校验非空即可 |

要求：

* 前端预校验：仅需确保账号满足 10 位数字正则（如 `/^\d{10}$/`），且密码不为空。不需要再进行复杂的密码复杂度正则校验（因为注册时已经拦截过了）。
* 后端校验逻辑：去数据库依据 `accountNo` 查询用户。如果用户不存在，或存在的用户的 `password_hash` 经 Bcrypt 对比后不匹配，**统一拦截**。
* **安全铁律**：无论是因为“账号不存在”还是“密码错误”导致的失败，对外的错误提示必须模糊处理为“账号或密码错误”，严禁给黑客提供遍历系统中有效账号的机会。
* 后端验证通过后，需使用系统密钥签发一段 JWT Token 字符串供前端后续鉴权使用。

成功响应格式：

```json
{
	"code": 200,
	"message": "success",
	"data": {
		"token": "身份令牌",
		"userName": "昵称"	// 返回昵称供前端UI展示
	}
}
```

失败响应格式：

```json
{
	"code": 根据错误类型返回,
	"message": "具体错误分类",
	"data": null
}
```

接口返回约束：


| **业务场景**   | **Code** | **Message (供前端直接作为 Toast 提示语)** | **底层逻辑说明**                                            |
| -------------- | -------- | ----------------------------------------- | ----------------------------------------------------------- |
| **正常成功**   | `200`    | `"登录成功！欢迎回来"`                    | 账号密码匹配，Token 签发完毕                                |
| **账号格式错** | `400`    | `"登录失败：账号格式不正确"`              | 后端校验`accountNo` 不是 10 位纯数字                        |
| **参数缺失**   | `400`    | `"登录失败：请填写账号和密码"`            | `accountNo` 或 `password` 为空                              |
| **凭证错误**   | `401`    | `"登录失败：账号或密码错误"`              | 账号不存在，或 Bcrypt 密码比对失败（HTTP 401 Unauthorized） |
| **系统异常**   | `500`    | `"服务器繁忙，登录失败，请稍后再试"`      | 数据库连接失败或 Token 生成模块崩溃                         |
