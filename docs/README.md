# 文档索引

本目录保存项目分析设计文档。正式开发时优先阅读本索引，再进入对应设计文档。

## 文档定位

| 文档 | 定位 | 适合回答的问题 |
| --- | --- | --- |
| `需求文档.md` | 产品方向说明 | 项目为什么做、边界是什么、阶段规划是什么 |
| `需求规格说明书.md` | 产品需求基线 | 系统要做什么、用户是谁、功能范围和验收标准是什么 |
| `概要设计.md` | 总体技术方案 | 系统整体怎么分层、前后端怎么协作、核心模块是什么 |
| `详细设计.md` | 落地实现方案 | 静态结构、动态流程、服务职责、关键伪代码、开发顺序是什么 |
| `数据库设计.md` | 数据持久化方案 | 系统库有哪些表、字段、约束、索引，用户物理库怎么管理 |
| `接口规范.md` | 唯一权威接口文档 | 前后端接口路径、请求参数、响应格式、错误码是什么 |
| `安全设计.md` | 安全与防护方案 | 双 Token、权限、SQL 安全、文件安全、容量限制、防御策略是什么 |

## Markdown 与 LaTeX 关系

Markdown 文档是需求和设计内容的唯一维护源。修改内容时应优先编辑本目录下的 `.md` 文件，再运行：

```txt
python docs/latex/build_latex.py
```

生成脚本会从 Markdown 重新生成 `docs/latex/src` 中的 LaTeX 源码和 `docs/latex/pdf` 中的 PDF，避免 Markdown 与 LaTeX/PDF 内容分叉。

生成映射如下：

| PDF 文档 | Markdown 来源 |
| --- | --- |
| `需求文档.pdf` | `需求文档.md` |
| `需求规格说明书.pdf` | `需求规格说明书.md` |
| `概要设计说明书.pdf` | `概要设计.md` |
| `详细设计说明书.pdf` | `详细设计.md`、`数据库设计.md`、`安全设计.md` |
| `接口文档.pdf` | `接口规范.md` |

## 数据库设计位置

数据库设计统一维护在：

```txt
docs/数据库设计.md
```

其中包含：

- 系统库表结构。
- 用户物理库命名规则。
- 范式设计。
- 元数据来源。
- 索引设计。
- 容量限制相关数据依据。
