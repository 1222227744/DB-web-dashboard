# 接口规范

本文档是项目唯一权威接口文档。早期登录注册草稿《接口文档.md》已合并到本文档，不再单独维护，避免接口设计和接口文档重复导致实现偏差。

## 1. 接口总则

### 1.1 Base URL

```txt
/api/v1
```

### 1.2 成功响应

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "traceId": "01HZ0000000000000000000000"
}
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| code | number | 是 | 成功固定为 200 |
| message | string | 是 | 成功提示 |
| data | any | 是 | 无数据时为 null |
| traceId | string | 是 | 服务端生成，请求级唯一 |

### 1.3 错误响应

```json
{
  "code": 400,
  "message": "字段 age 不允许为空",
  "data": null,
  "traceId": "01HZ0000000000000000000000",
  "error": {
    "type": "MYSQL_CONSTRAINT_ERROR",
    "code": "DB_NOT_NULL_VIOLATION",
    "source": "mysql",
    "details": "Column 'age' cannot be null",
    "fieldErrors": [
      {
        "field": "age",
        "message": "字段 age 不允许为空"
      }
    ],
    "mysql": {
      "errno": 1048,
      "sqlState": "23000",
      "sqlMessage": "Column 'age' cannot be null",
      "databaseName": "student",
      "tableName": "students",
      "columnName": "age",
      "constraintName": null
    }
  }
}
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| code | number | 是 | 与 HTTP 状态语义一致 |
| message | string | 是 | 前端直接展示的精准提示 |
| data | null | 是 | 错误时固定为 null |
| traceId | string | 是 | 请求级唯一 |
| error.type | string | 是 | 错误类型枚举 |
| error.code | string | 是 | 错误码枚举 |
| error.source | string | 是 | client、server、mysql |
| error.details | string | 是 | 错误详情，不包含密码和 Token |
| error.fieldErrors | array | 是 | 字段级错误列表 |
| error.mysql | object | 是 | 非 MySQL 错误时为 null |

### 1.4 前端本地错误模型

以下错误没有后端响应，由前端统一构造展示：

- 无法连接后端：`type=NETWORK_ERROR`；`code=CLIENT_BACKEND_UNREACHABLE`；`message=无法连接后端服务，请检查服务是否启动`。
- 请求超时：`type=HTTP_TIMEOUT`；`code=CLIENT_REQUEST_TIMEOUT`；`message=后端响应超时，请稍后重试`。
- 请求被浏览器取消：`type=CLIENT_ABORTED`；`code=CLIENT_REQUEST_ABORTED`；`message=请求已取消`。

### 1.5 HTTP 状态码

| HTTP | error.type | 使用场景 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 参数格式错误、字段校验失败 |
| 401 | AUTH_ERROR | 未登录、Access Token 失效、登录凭证错误 |
| 403 | AUTHZ_ERROR | 已登录但无权访问资源 |
| 404 | RESOURCE_NOT_FOUND | 数据库、表、字段、索引、视图不存在 |
| 409 | RESOURCE_CONFLICT | 名称重复、状态冲突 |
| 412 | CONFIRMATION_REQUIRED | 缺少确认信息 |
| 413 | LIMIT_EXCEEDED | 容量超限 |
| 429 | RATE_LIMITED | 请求过于频繁 |
| 500 | INTERNAL_ERROR | 服务端未预期异常 |
| 502 | MYSQL_CONNECTION_ERROR | MySQL 连接失败 |
| 503 | MYSQL_UNAVAILABLE | MySQL 不可用 |

## 2. 通用参数约束

### 2.1 标识符

数据库显示名、表名、字段名、索引名、约束名、视图名：

```txt
^[A-Za-z][A-Za-z0-9_]{0,63}$
```

### 2.2 分页

| 参数 | 类型 | 必填 | 默认值 | 约束 |
| --- | --- | --- | --- | --- |
| page | number | 否 | 1 | 整数，最小 1 |
| pageSize | number | 否 | 20 | 整数，最小 1，最大 100 |

### 2.3 确认对象

高风险请求统一使用：

```json
{
  "confirmation": {
    "confirmed": true,
    "confirmText": "students",
    "disableSameTypePrompt": false
  }
}
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| confirmed | boolean | 是 | 必须为 true |
| confirmText | string | 是 | 必须与后端要求文本完全一致 |
| disableSameTypePrompt | boolean | 否 | 只对中风险操作生效 |

强制确认操作忽略 `disableSameTypePrompt`。

### 2.4 默认容量限制

| 限制项 | 默认值 |
| --- | --- |
| 单用户数据库数量 | 10 |
| 单数据库表数量 | 100 |
| 单数据库视图数量 | 50 |
| 单表字段数量 | 80 |
| 单表索引数量 | 16 |
| 单用户物理数据总量 | 1GB |
| 单数据库物理数据量 | 512MB |
| 单表物理数据量 | 256MB |
| 单次分页返回行数 | 100 |
| 单次查询最大返回行数 | 1000 |
| 单次批量新增行数 | 500 |
| 单次批量修改影响行数 | 200 |
| 单次批量删除影响行数 | 200 |
| 查询最大 JOIN 数 | 8 |
| 查询最大子查询深度 | 3 |
| 查询最大执行时间 | 10 秒 |
| 查询 AST 最大体积 | 64KB |
| 头像文件大小 | 2MB |
| 背景图文件大小 | 8MB |
| 单用户资源总量 | 100MB |

服务端可以通过配置调整默认值。接口文档中的默认值用于本地课程项目落地。

## 3. 错误码枚举

### 3.1 通用错误码

| code | message 模板 |
| --- | --- |
| VALIDATION_FIELD_REQUIRED | `{field} 为必填项` |
| VALIDATION_IDENTIFIER_INVALID | `{field} 名称格式不正确` |
| VALIDATION_ENUM_INVALID | `{field} 不在允许范围内` |
| RESOURCE_NOT_FOUND | `{resource} 不存在` |
| RESOURCE_CONFLICT | `{resource} 已存在` |
| AUTH_TOKEN_MISSING | `登录状态缺失，请重新登录` |
| AUTH_TOKEN_EXPIRED | `登录已过期，请重新登录` |
| AUTH_CREDENTIAL_INVALID | `账号与密码不匹配` |
| AUTHZ_DATABASE_FORBIDDEN | `无权访问该数据库` |
| CONFIRMATION_TEXT_MISMATCH | `确认文本不匹配` |
| LIMIT_EXCEEDED | `操作超过系统限制` |
| INTERNAL_ERROR | `服务端异常，请联系维护者并提供追踪编号` |

### 3.2 MySQL 错误码映射

- `1044` / `42000`：`DB_ACCESS_DENIED`；`数据库访问被拒绝`。
- `1045` / `28000`：`DB_AUTH_FAILED`；`数据库账号认证失败`。
- `1046` / `3D000`：`DB_NOT_SELECTED`；`未选择数据库`。
- `1048` / `23000`：`DB_NOT_NULL_VIOLATION`；`字段 {columnName} 不允许为空`。
- `1050` / `42S01`：`DB_TABLE_EXISTS`；`表 {tableName} 已存在`。
- `1051` / `42S02`：`DB_TABLE_NOT_FOUND`；`表 {tableName} 不存在`。
- `1054` / `42S22`：`DB_COLUMN_NOT_FOUND`；`字段 {columnName} 不存在`。
- `1062` / `23000`：`DB_DUPLICATE_ENTRY`；`唯一约束冲突：{constraintName}`。
- `1064` / `42000`：`DB_SQL_SYNTAX_ERROR`；`系统生成的 SQL 语法错误`。
- `1072` / `42000`：`DB_KEY_COLUMN_NOT_FOUND`；`索引字段 {columnName} 不存在`。
- `1215` / `HY000`：`DB_FOREIGN_KEY_CREATE_FAILED`；`外键创建失败`。
- `1216` / `23000`：`DB_FOREIGN_KEY_CHILD_FAILED`；`外键约束失败，引用数据不存在`。
- `1217` / `23000`：`DB_FOREIGN_KEY_PARENT_FAILED`；`外键约束失败，存在关联数据`。
- `1451` / `23000`：`DB_FOREIGN_KEY_RESTRICT`；`存在关联数据，删除被外键限制`。
- `1452` / `23000`：`DB_FOREIGN_KEY_REFERENCE_MISSING`；`外键引用的目标数据不存在`。
- `3819` / `HY000`：`DB_CHECK_CONSTRAINT_FAILED`；`检查约束 {constraintName} 不满足`。

## 4. 认证接口

### API-AUTH-001 注册

```txt
POST /api/v1/auth/register
```

请求体：

| 参数 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| userName | string | 是 | trim 后长度 2-20 |
| password | string | 是 | 8-16 位，包含英文字母和数字 |

成功响应 `data`：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| accountNo | string | 10 位数字 |
| userName | string | 展示昵称 |

错误：

| code | message |
| --- | --- |
| VALIDATION_FIELD_REQUIRED | 昵称和密码均为必填项 |
| VALIDATION_PASSWORD_INVALID | 密码必须为 8-16 位且包含英文字母和数字 |
| INTERNAL_ERROR | 注册失败，请提供追踪编号联系维护者 |

### API-AUTH-002 登录

```txt
POST /api/v1/auth/login
```

请求体：

| 参数 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| accountNo | string | 是 | 10 位数字 |
| password | string | 是 | 非空字符串 |

成功响应 `data`：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| accessToken | string | JWT |
| user.userID | number | 用户 ID |
| user.accountNo | string | 10 位账号 |
| user.displayName | string | 展示昵称 |

Refresh Token 通过 HttpOnly Cookie 写入。

错误：

| code | message |
| --- | --- |
| VALIDATION_IDENTIFIER_INVALID | 账号格式不正确 |
| AUTH_CREDENTIAL_INVALID | 账号与密码不匹配 |
| MYSQL_CONNECTION_ERROR | 数据库连接失败，登录未完成 |

### API-AUTH-003 刷新 Token

```txt
POST /api/v1/auth/refresh
```

请求：

- 无请求体。
- 必须携带 Refresh Token Cookie。

成功响应 `data`：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| accessToken | string | 新 Access Token |

错误：

| code | message |
| --- | --- |
| AUTH_REFRESH_MISSING | 刷新凭证缺失，请重新登录 |
| AUTH_REFRESH_EXPIRED | 登录状态已失效，请重新登录 |
| AUTH_REFRESH_REUSE_DETECTED | 登录状态异常，请重新登录 |

### API-AUTH-004 退出登录

```txt
POST /api/v1/auth/logout
```

请求：

- 必须携带 Refresh Token Cookie。

成功响应：

```json
{
  "code": 200,
  "message": "退出登录成功",
  "data": null,
  "traceId": "01HZ0000000000000000000000"
}
```

### API-ASSET-001 上传用户资源

```txt
POST /api/v1/users/me/assets
```

请求体：

| 参数 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| assetType | string | 是 | avatar、background |
| originalName | string | 是 | 原始文件名，服务端清理危险字符 |
| mimeType | string | 是 | image/png、image/jpeg、image/webp |
| dataBase64 | string | 是 | base64 或 data URL |

规则：

- 头像最大 2 MB，背景图最大 8 MB，单用户资源总量最大 100 MB。
- 文件保存到服务端资源目录，系统库只保存元信息和归属关系。
- 上传头像后自动更新 `user_profiles.avatar_asset_id`。
- 上传背景后自动更新 `user_preferences.background_mode=image` 和 `background_asset_id`。

### API-ASSET-002 读取用户资源

```txt
GET /api/v1/users/me/assets/:assetId
```

规则：

- 必须登录。
- 只能读取归属当前用户的资源。
- 响应体为图片二进制，`Content-Type` 使用资源 MIME 类型。

### API-TABLE-002 创建表

```txt
POST /api/v1/databases/:databaseId/tables
```

请求体：

| 参数 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| tableName | string | 是 | 标识符规则 |
| columns | array | 是 | 长度 1 到服务端上限 |
| constraints | array | 否 | 约束定义 |
| indexes | array | 否 | 索引定义 |

说明：创建表不强制必须包含主键；无主键表允许预览和新增，行内更新和删除按无主键表策略锁定。

`columns[]`：

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| name | string | 是 | 标识符规则 |
| type | string | 是 | 支持的数据类型 |
| length | number | 否 | CHAR 使用 1-255，VARCHAR 使用 1-16383 |
| precision | number | 否 | DECIMAL 使用，1-65 |
| scale | number | 否 | DECIMAL 使用，0 到 precision |
| unsigned | boolean | 否 | 数值类型使用 |
| nullable | boolean | 是 | 布尔值 |
| defaultValue | any | 否 | 与字段类型兼容 |
| autoIncrement | boolean | 否 | 整数类型使用 |
| comment | string | 否 | 最大 255 字符 |

支持的数据类型：

```txt
TINYINT, SMALLINT, INT, BIGINT, DECIMAL, FLOAT, DOUBLE,
CHAR, VARCHAR, TEXT, MEDIUMTEXT, LONGTEXT,
DATE, TIME, DATETIME, TIMESTAMP, BOOLEAN, JSON,
BLOB, MEDIUMBLOB, LONGBLOB
```

`constraints[]`：

- `name`：`string`；必填；标识符规则。

- `referencedTable`：`string`；条件必填；外键使用。
- `referencedColumns`：`array`；条件必填；外键使用。
- `onDelete`：`string`；条件必填；取值为 `RESTRICT`、`CASCADE`、`SET NULL`、`NO ACTION`。
- `onUpdate`：`string`；条件必填；取值为 `RESTRICT`、`CASCADE`、`SET NULL`、`NO ACTION`。
- `column`：`string`；条件必填；`CHECK_IN` 使用，表示有限取值字段。
- `values`：`array`；条件必填；`CHECK_IN` 使用，长度 1 到 50，仅支持字符串、数字或布尔值。

阶段说明：创建表接口支持可选 `PRIMARY_KEY`、`UNIQUE`、`FOREIGN_KEY` 和 `CHECK_IN`。当前前端创建表弹窗先暴露字段、主键和默认值，更多索引/约束通过结构管理窗口或接口使用。

### API-ROW-002 新增数据

```txt
POST /api/v1/databases/:databaseId/tables/:tableName/rows
```

请求体：

| 参数 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| row | object | 条件必填 | 字段名到字段值的对象，至少包含一个字段 |
| rows | array | 条件必填 | 批量新增行数组，长度 1 到 `maxBatchInsertRows` |
| confirmation | object | 条件必填 | `rows` 超过 1 行时必填 |

规则：

- 字段名必须存在于目标表。
- `auto_increment` 字段可以不提交，由 MySQL 自动生成。
- 前端新增行时空白字段默认不提交，避免误写入 `NULL`。
- 批量新增由前端弹窗输入 JSON 数组或导入 CSV 文件；CSV 导入支持 UTF-8、GBK 编码和跳过起始行数。
- 后端按表结构校验数字、布尔、JSON 和非空字段。
- 单表容量达到限制时拒绝新增。

| row | object 或 null | 可通过主键回读时返回新增后的行 |

| rows | array | 批量新增时返回逐行结果 |
| primaryKeys | array | 批量新增时返回逐行主键 |
| affectedRows | number | 影响行数 |

### API-ROW-003 修改数据

```txt
PATCH /api/v1/databases/:databaseId/tables/:tableName/rows
```

请求体：

| 参数 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| primaryKey | object | 条件必填 | 完整主键字段和值 |
| primaryKeys | array | 条件必填 | 完整主键对象数组 |
| set | object | 是 | 字段名到新值的对象 |
| confirmation | object | 条件必填 | `primaryKeys` 超过 1 行时必填 |

行内编辑提交规则：

- 用户在前端表格中直接修改单元格时，前端只保存本地草稿，不立即调用该接口。
- 用户点击该行旁边“更新/提交”按钮后，前端调用该接口。
- 后端使用 `primaryKey` 定位唯一行。
- `set` 只提交被修改字段，不提交整行数据。
- `primaryKey` 字段和 `auto_increment` 字段不允许通过行内编辑修改。
- 用户点击“取消”时前端丢弃草稿，不调用后端。
- 批量修改使用 `primaryKeys` 定位已选行，当前前端一次修改一个非主键非自增字段。
- 无主键表在 V5 阶段禁止行内编辑。
- 单表容量达到限制时拒绝更新。

行内编辑请求示例：

```json
{
  "primaryKey": {
    "id": 1
  },
  "set": {
    "name": "Alice",
    "age": 18
  }
}
```

错误：

| code | message |
| --- | --- |
| PRIMARY_KEY_REQUIRED | 当前表没有主键，暂不支持行级修改或删除 |
| ROW_UPDATE_NOT_UNIQUE | 更新目标不存在或不唯一，请刷新后重试 |
| VALIDATION_FIELD_INVALID | 字段不存在、类型不合法或字段不允许修改 |
| MYSQL_EXECUTION_ERROR | 更新行失败：{mysql.sqlMessage} |

### API-ROW-005 批量数据操作

批量新增、基于主键列表的批量修改和基于主键列表的批量删除已经并入 `API-ROW-002` 至 `API-ROW-004`。批量写入规则如下：

- 批量新增使用 `rows` 数组，单次最多 `maxBatchInsertRows` 行。
- 批量修改和批量删除使用 `primaryKeys` 数组，单次最多 `maxBatchWriteAffectedRows` 行。
- 超过单行时必须提交 `confirmation.confirmed=true`，且 `confirmation.confirmText` 等于表名。
- 同一批次在事务中执行，全成功才提交；任意一行失败则回滚。基于 GUI 条件对象的批量修改/删除归入查询构造器阶段。
